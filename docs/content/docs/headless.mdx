Use the headless API when you want to supply every component yourself, including MUI, Chakra, or your own design system. The hooks and provider render no wrapper elements or browser dialogs. Default UI styles load only when you render the default `Quiz` component. The default `Quiz` component uses the same engine.

```jsx
import { useQuiz } from 'react-quiz-component';

function CustomQuiz({ quiz }) {
  const { state, actions } = useQuiz({ quiz });
  if (state.status === 'invalid') return <p>{state.errors.join(' ')}</p>;
  if (state.status === 'idle')
    return <button onClick={actions.start}>Start</button>;
  if (state.status === 'completed')
    return (
      <p>
        Score: {state.summary.correctPoints} / {state.summary.totalPoints}
      </p>
    );
  return (
    <section>
      <h2>{state.currentQuestion?.question}</h2>
      {state.answers.map((answer) => (
        <button
          key={answer.answerNumber}
          disabled={answer.disabled}
          aria-pressed={answer.selected}
          onClick={() => actions.selectAnswer(answer.answerNumber)}
        >
          {answer.value}
        </button>
      ))}
      <p aria-live="polite">{state.feedback}</p>
      {state.canGoNext && <button onClick={actions.nextQuestion}>Next</button>}
      {state.canSubmit && <button onClick={actions.submitQuiz}>Finish</button>}
    </section>
  );
}
```

For separate question, timer, navigation, and result components, share a session through context:

```jsx
import { QuizProvider, useQuizContext } from 'react-quiz-component';

function StartButton() {
  const { state, actions } = useQuizContext();
  return state.canStart ? <button onClick={actions.start}>Start</button> : null;
}

function App({ quiz }) {
  return (
    <QuizProvider quiz={quiz}>
      <StartButton />
    </QuizProvider>
  );
}
```

`QuizProvider` accepts the same options as `useQuiz` and adds no DOM element. Each provider or standalone hook owns an independent session. `useQuizContext()` throws an error without an ancestor `QuizProvider`. Calling `useQuiz()` inside a provider creates a **new** session; use `useQuizContext()` to access the shared one. Import the hooks, provider, and their TypeScript types directly from `react-quiz-component`; no subpath is required.

## Server rendering and shuffling

The engine prepares random orders when a session is created. If your headless interface displays shuffled questions or answers during server rendering, the browser can prepare a different order during hydration. A `'use client'` directive alone does not prevent server rendering in Next.js.

Keep the initial output independent of shuffled state, such as a Start button, or mount your quiz inside a client-only wrapper:

```jsx
'use client';
import { useSyncExternalStore } from 'react';

const subscribe = () => () => {};
const getClientSnapshot = () => true;
const getServerSnapshot = () => false;

export function ClientOnly({ children }) {
  const hydrated = useSyncExternalStore(subscribe, getClientSnapshot, getServerSnapshot);
  return hydrated ? children : null;
}
```

Wrap the component that calls `useQuiz`, or the entire `QuizProvider` and its consumers, with `<ClientOnly>`. The session then starts when the wrapper mounts, including its timer. This is needed even without `autoStart` if your initial UI renders shuffled state. The default `Quiz` component handles its own auto-started shuffled view; see [Server rendering](./component.mdx#server-rendering).
